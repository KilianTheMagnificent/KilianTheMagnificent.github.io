Technical notes · St. Louis, MO

Personal repositories and technical notes on verifying AI-assisted software without reading code, coordinating parallel coding agents with CI oracles, input validation, and machine-checked Lean 4 verification—specifically what breaks when untrusted files, inbound mail, CSV exports, concurrent agent worktrees, or AI-generated proof scripts pass into compilers, spreadsheets, CI runners, or external model APIs without explicit checks in front of them. All tamper/bypass modules, disguised binary headers, CSV formula strings, and hidden HTML/Unicode markers referenced below are synthetic local regression fixtures in these repositories.

    Coordinating Coding Agents and Catching Real Bugs with CI Oracles

    How a non-coder isolates parallel coding agents behind a worktree protocol (wcp) and uses multi-version Linux GitHub Actions CI as an independent oracle to catch real bugs without reading code. Documents five verified bugs across wcp (232 tests: Python 3.14 SQLite ResourceWarnings, Linux fchmodat(AT_SYMLINK_NOFOLLOW) replaced with O_NOFOLLOW + os.fstat + os.fchmod, a PID-1 grandchild reaping race, and a real Runner.summary() pause-race) and luck-filter (55 tests: glibc lgamma/exp rounding drift at binomial_test(0, 10, 0.5) plus the p0 == 1.0 boundary fix).

  • 2026-11-16 (updated 2026-11-18)

    Screening Untrusted Office Inputs Before LLM Triage

    Design and known limits of inbox-guard, a zero-dependency Node.js library that screens inbound business emails, attachments, and CSV exports before model calls or human review. Covers leading magic-byte checks (MZ/ELF/Mach-O/archives renamed to document extensions), Unicode U+202E and Windows/SMB filename spoofing, accounting-safe OWASP CSV neutralization and RFC-4180 serialization, linear HTML5 comment and CSS declaration scanning, Plane-14 Unicode Tag (U+E0000..U+E007F) stripping, RFC 5322 sender spoofing, and randomized session-scoped PII tokenization.
