Technical notes · St. Louis, MO

Personal repositories and technical notes on input validation and machine-checked Lean 4 verification—specifically what breaks when untrusted files, inbound mail, CSV exports, or AI-generated proof scripts pass into compilers, spreadsheets, or external model APIs without explicit checks in front of them. All tamper/bypass modules, disguised binary headers, CSV formula strings, and hidden HTML/Unicode markers referenced below are synthetic local regression fixtures in these repositories.

    Checking Untrusted AI-Authored Lean 4 Proofs

    Why lake build plus a sorry grep fails when unattended coding agents write Lean proofs. Walks through open-proofs (where proofs and tooling were built with Claude Code and Codex and verified by a 5-layer checker: integrity, lint, clean build, opcheck, leanchecker), the 48 self-test checks in tests/run_adversarial.py (41 negative tamper/bypass checks plus 7 positive controls), checker scope limits, and the negation proofs behind google-deepmind/formal-conjectures#7590.

  • 2026-11-16 (updated 2026-11-18)

    Screening Untrusted Office Inputs Before LLM Triage

    Design and known limits of inbox-guard, a zero-dependency Node.js library that screens inbound business emails, attachments, and CSV exports before model calls or human review. Covers leading magic-byte checks (MZ/ELF/Mach-O/archives renamed to document extensions), Unicode U+202E and Windows/SMB filename spoofing, accounting-safe OWASP CSV neutralization and RFC-4180 serialization, linear HTML5 comment and CSS declaration scanning, Plane-14 Unicode Tag (U+E0000..U+E007F) stripping, RFC 5322 sender spoofing, and randomized session-scoped PII tokenization.
