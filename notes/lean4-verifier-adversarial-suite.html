Checking Untrusted AI-Authored Lean 4 Proofs

In open-proofs, AI agents (Claude Code and Codex) write Lean 4 proofs of placeholder declarations from google-deepmind/formal-conjectures, and no human reads the proof scripts line by line. Trust rests entirely on the checker. This note documents how a naive lake build check can be cheated, how the 5-layer checker and its 48-case adversarial suite close those paths, what the checker still does not guarantee, and how automated negation proofs surfaced the misformalizations reported in formal-conjectures#7590.

1. Why lake build + Grepping for sorry Fails

Lean's kernel checks elaborated proof terms, not surface source files or build scripts. When an unattended agent has write access to a workspace and is told to prove a theorem, a script that compiles with lake build and contains no literal sorry token can still fail to prove the intended theorem in at least five ways:

  • Statement drift or shadowing: Adding an extra hypothesis (h : k < 0 on k : ℕ), defining a local Erdos349.IsGoodPair inside a nested namespace so the text matches upstream while resolving to True, or declaring a high-priority local instance : LE ℕ where ≤ means True.
  • Transitive placeholder laundering: Proving the candidate theorem by applying the upstream theorem directly—whose own body in formal-conjectures is still sorry—or hiding sorry behind a tactic macro or helper module.
  • Compiler-trust attributes and tactics: Using native_decide (which introduces Lean.ofReduceBool / Lean.trustCompiler), @[extern], or @[implemented_by] so compiled code diverges from kernel reduction.
  • Elaboration-time environment mutation: Running set_option debug.skipKernelTC true with run_cmd and addDecl to insert a proof of False backed by True.intro. No axiom appears anywhere in the resulting constant's body.
  • Workspace tampering: Editing files inside .lake/packages/formal_conjectures, adding moreLeanArgs = ["-Ddebug.skipKernelTC=true"] to lakefile.toml, or leaving a stale .olean from an earlier build.

2. The Five Checker Layers

scripts/check.py (check_claim, lines 259–297) passes a claim only when all five layers pass. Every recorded verdict in ledger/results.json includes the SHA-256 hash of the checker files themselves (TRUSTED_BASE, lines 50–58 and 146–154).

Layer 1 — integrity (scripts/check.py, lines 91–144)

Checks workspace pins before touching candidate code:

  • Verifies lean-toolchain matches upstream.json (leanprover/lean4:v4.33.1), and that lakefile.toml and lake-manifest.json match the pinned commits for formal_conjectures (96343eeb5990ff13735e728cd0195eff0156a3bb) and mathlib (0df444a360eaa60ab8c11dca51a86af692955474).
  • Rejects lakefile.lean outright (Lean lakefiles execute arbitrary code during configuration) and scans lakefile.toml against 15 forbidden keys (FORBIDDEN_LAKEFILE_KEYS: moreLeanArgs, weakLeanArgs, moreServerArgs, plugins, dynlibs, loadDynlibPaths, precompileModules, nativeFacets, etc.) plus regexes for debug., skipKernelTC, trustLevel, and \btrust\b.
  • Runs git rev-parse HEAD and git status --porcelain --untracked-files=all inside every checkout under .lake/packages/, rejecting both tracked edits and untracked files.

Layer 2 — lint (scripts/lint.py, lines 23–215)

Walks the OpenProofs.* source import closure (source_closure, lines 221–237) and applies role-specific source rules before any Lean build runs:

  • Stripped pass (RESULT_CODE_RULES, 29 rules): strip_comments_and_strings (lines 98–145) blanks line comments, nested /- ... -/ block comments, string literals, and character literals while keeping line numbers intact, then bans sorry, admit, stop, axiom, opaque, unsafe, partial, implemented_by, extern, export, csimp, @[init], native_decide, +native, ofReduceBool/reduceBool/trustCompiler, macro/syntax/elab/notation, run_cmd/run_elab/run_meta/run_tac, #eval/#exit, initialize, debug.*, skipKernelTC, set_option trust, addDecl*/modifyEnv/setEnv, and Lean.(Elab|Meta|Kernel|Compiler|Parser|PrettyPrinter).
  • Raw text pass (RAW_RULES, 9 rules): Scans the unstripped source text for sorry, admit, native_decide, implemented_by, skipKernelTC, ofReduceBool/trustCompiler, run_cmd/run_tac/run_elab/run_meta, #eval, and addDecl*. Result files may not write those words even inside comments or strings, making comment/string parser edge cases irrelevant for them.
  • Import allowlists & statement files: Proof files may import only Mathlib, Batteries, Aesop, Plausible, FormalConjectures*, and OpenProofs.{Results,Lib}.*. Self-recorded variant statements in OpenProofs/Statements/ may contain only theorem ... := sorry declarations—no def, abbrev, instance, structure, notation, or variable (STATEMENT_FORBIDDEN_DECL, lines 78–84).

Layer 3 — Clean build (scripts/check.py, lines 183–199)

clean_outputs deletes existing .olean, .ilean, and IR files under .lake/build/lib/lean and .lake/build/ir for all candidate modules in the source closure before running lake build, so compiled artifacts always match current source.

Layer 4 — opcheck (OpenProofsChecker/Main.lean, lines 230–411)

opcheck is a standalone Lean executable that inspects compiled .olean files without importing candidate modules at compile time. It loads the candidate module and reference module with extension hooks disabled (lines 246–249): 

let env <- importModules #[{ module := args.module }, { module := args.refModule }] {}
  (trustLevel := 0) (loadExts := false) (level := .private)

With loadExts := false and trustLevel := 0, imported modules cannot execute @[init] blocks, environment-extension hooks, or pretty-printer extensions during inspection. opcheck emits nine check results:

  1. module_origins (lines 111–125, 251–259): Resolves IO.FS.realPath on every loaded .olean and classifies it into core, package:<name>, or candidate; fails on any unknown path.
  2. ref_trusted (lines 264–276): Confirms the reference declaration is a .thmInfo defined in .lake/packages/formal_conjectures (FormalConjectures.*) for upstream claims, or OpenProofs.Statements.* for variant claims.
  3. theorem_found (lines 278–286): Confirms the claimed theorem is a non-unsafe .thmInfo declared in the candidate module itself.
  4. statement_match (lines 292–314): Aligns universe parameters and compares ci.type against refCi.type as elaborated Expr values (syntactic identity). If they differ syntactically (for example, different typeclass instance paths that are definitionally equal), opcheck asks the kernel directly via Kernel.Environment.addDecl to typecheck theorem _opcheck_statement_bridge : <refCi.type> := <args.thm> (kernel-defeq identity).
  5. statement_consts (lines 316–324): Verifies every constant in refCi.type.getUsedConstants comes from a trusted non-candidate module.
  6. axioms (lines 143–166, 326–337): Walks every constant body and type reachable from the theorem (walkAxioms) without reading precomputed .olean axiom metadata. Only propext, Classical.choice, and Quot.sound are allowed.
  7. closure_clean (lines 339–346): Rejects candidate closures that import OpenProofs.Statements.* or OpenProofsChecker.*.
  8. candidate_decls (lines 348–396): Scans all constants across candidate modules in the closure (stripping private prefixes via privateToUserName?). Rejects axiom, opaque, quot, unsafe, partial, @[implemented_by], @[extern], @[export], and @[init]. Enforces the OpenProofs. namespace—allowing outside it only compiler-realized equation theorems (f.eq_<digits>, f.eq_def, f.eq_unfold) of non-candidate definitions—and checks properSuffixes so no candidate declaration shadows a trusted definition, structure, or instance.
  9. kernel_replay (lines 169–188, 398–408): Re-reads raw module data parts (.olean, .olean.server, .olean.private) and replays all candidate constants from scratch on top of clean imports via env.replay.

Layer 5 — leanchecker (scripts/check.py, lines 227–235)

Runs lake env leanchecker <module> in a separate process for every candidate module in the closure.

3. The 48 Adversarial Self-Tests

tests/run_adversarial.py verifies 48 expectations across three groups: 10 source-lint unit tests (run_lint), 9 integrity tamper checks (run_integrity), and 29 end-to-end Lean claims in tests/adversarial/cases.json (25 cheat or hygiene-violation cases that must FAIL, plus 4 positive controls—HonestFixture, HonestDecide, RealizedEqLemma, and LibGoodUse—that must PASS).

Each entry in cases.json specifies both must_fail and optional must_pass checks so a change in one layer cannot silently mask a regression in another:

Category Cases in run_adversarial.py What Passes vs. What Rejects It
Foreign / compiler substitution Extern, ImplementedBy, NativeDecide, OpaqueDecl, UnsafePartial, lint/csimp_flagged Extern and ImplementedBy pass axioms and statement_match (the theorem body itself uses norm_num), and are rejected by both lint and opcheck:candidate_decls. NativeDecide passes statement_match and fails lint and opcheck:axioms.
Axiom & placeholder laundering SorryDirect, MacroSorry, SorryViaUpstream, ImportsStatement, LibSorryUse, LibSorryUnused, CustomAxiom, AxiomClaim SorryViaUpstream cites the upstream placeholder theorem directly; it passes lint and statement_match, and is caught by opcheck:axioms walking into upstream's sorryAx. LibSorryUnused proves its theorem honestly with decide while importing a helper module containing sorry; axioms passes, lint rejects the closure.
Statement spoofing & shadowing WeakenedStatement, ShadowDef, InstanceOverride, CandidateDef, FakeEqLemma, OutsideNamespace, UpstreamNamespaceHelper ShadowDef (redefining Erdos349.IsGoodPair as True) and InstanceOverride (high-priority LE ℕ returning True) pass lint and axioms, and fail opcheck:statement_match (plus candidate_decls for ShadowDef). FakeEqLemma forges Erdos349.IsGoodPair.eq_helper and fails candidate_decls while RealizedEqLemma (eq_1) passes.
Kernel-bypass environment edit SkipKernelTC Uses set_option debug.skipKernelTC true + run_cmd addDecl to inject cheat : False := True.intro. Both statement_match and axioms pass; rejected independently by lint, opcheck:kernel_replay, and leanchecker.
Lexer & workspace tampering 10 lint/* cases + 9 integrity/* cases Tests quote-in-char-literal (def c := '"') before sorry, unterminated string literals before native_decide, nested block comments before axiom, tracked edits and untracked files in .lake/packages/formal_conjectures, lakefile.lean injection, pin/toolchain mismatches, and skipKernelTC/plugins in lakefile.toml.

4. Upstream Misformalizations Found via Negation Proofs (#7590)

142 claims currently pass the checker in open-proofs: 131 proved targets (textbook theorems, test cases, and already-solved research variants whose upstream declarations still carried sorry) and 11 misformalization certificates across 8 Erdős problems.

Each of the 11 misformalizations follows the same pattern: an upstream value question quantifies over a parameter (k, N, c, or n), but types its answer(...) placeholder as a constant rather than a function of that parameter. As written, the formal theorem asserts that one fixed value works simultaneously for all values of the quantified parameter, making the statement false for every possible replacement of sorry.

On October 24, 2026, I filed google-deepmind/formal-conjectures#7590 covering the eight declarations across seven files still unchanged on upstream main (after earlier upstream issues covered the other three):

Upstream Statement Missing Parameter Why No Constant Answer Exists
erdos_142, erdos_142.variants.isTheta k r 0 N = N and r 2 N ≤ 1; no single function is asymptotic (or Θ) to both.
erdos_319 N Maximum is ≤ 1 at N = 1, and ≥ 3 at N = 6 via {2, 3, 6} (1/2 - 1/3 - 1/6 = 0).
erdos_321 N R 0 = 0 and R 1 ≥ 1.
erdos_361 c At n = 2, the count is 0 for c = 1/4 and 1 for c = 1.
erdos_409.variants.sigma n Least iteration count is 0 for n = 2 and positive for n = 6 (σ(6) - 1 = 11 is prime).
erdos_503 n In ℝ^0 the maximum is ≤ 1; in ℝ^1 it is ≥ 2.
erdos_692.parts.ii n Choosing n = m gives δ₁(m, m) = 0, while δ₁(m, m + 2) = 1/(m + 1) > 0.

Because referencing the upstream answer placeholder would pull sorryAx into the axiom walk, each certificate records and proves the answer-free universal negation (e.g., P319_no_constant_answer.lean proves ∀ a : ℕ, ¬ ∀ N : ℕ, IsGreatest { … } a using only propext, Classical.choice, and Quot.sound). Per repository policy (outbox/README.md), agents write drafts locally to outbox/ and never open issues or PRs themselves; human review and explicit AI disclosure happen manually before filing.

5. Scope & Known Limitations

  • Formal statement fidelity vs. informal intent: Passing all five layers verifies that the candidate proof term inhabits the elaborated Lean Expr of the reference theorem under the axioms {propext, Classical.choice, Quot.sound}. It does not check whether an upstream formalization faithfully captures the informal mathematical problem—which is why ledger/LEDGER.md separates checker verdicts from claim assessments.
  • Trusted computing base (TRUSTED_BASE): Verdicts depend on the integrity of TRUSTED_BASE hashed in scripts/check.py—lakefile.toml, lean-toolchain (v4.33.1), lake-manifest.json, upstream.json, OpenProofsChecker/Main.lean, scripts/check.py, and scripts/lint.py—along with the Lean 4 kernel, leanchecker, Python 3, git, and the pinned formal-conjectures (96343ee) and Mathlib (0df444a) revisions. Soundness bugs inside the Lean kernel or a compromised local toolchain binary are outside opcheck's scope.
  • Checker ≠ OS sandbox: Although integrity rejects lakefile.lean and plugins and lint rejects run_cmd, #eval, and Lean.Elab imports before lake build runs, scripts/check.py is an unverified Python driver, not an OS or VM sandbox. Unattended prover processes should still run inside filesystem- and network-isolated containers.
  • No open mathematical problem is solved in open-proofs: As stated in open-proofs/README.md, the 131 proved claims are textbook theorems, test statements, and previously solved research problems whose upstream Lean declarations were still sorry, alongside 11 negation certificates for misformalized value questions.

6. Reproduce

git clone https://github.com/KilianTheMagnificent/open-proofs.git
cd open-proofs
lake exe cache get
lake build
python3 scripts/check.py --all       # re-check all 142 claims
python3 tests/run_adversarial.py     # run all 48 self-test expectations
