Adversarial Soundness Testing for AI-Authored Lean 4 Proofs

When autonomous coding agents write formal proofs without line-by-line human review, running lake build and grepping for sorry is not a sound trust boundary. This note documents the 5-layer verification architecture in open-proofs, its 48-case adversarial self-test suite, and how machine-checked negation proofs surfaced quantified-parameter misformalizations reported in google-deepmind/formal-conjectures#7590.

1. Threat Model: Untrusted Provers in a Rich Elaborator

Interactive theorem provers based on dependent type theory follow the de Bruijn criterion: a small kernel checks elaborated proof terms, so buggy tactics cannot silently produce false theorems. That guarantee holds when a human trusts the surrounding build configuration, environment, and theorem statement. It breaks down when an unattended language-model agent has write access to a workspace and is rewarded for making a build succeed.

In open-proofs, AI agents (Claude Code and Codex) attempt open placeholder declarations (sorry) from google-deepmind/formal-conjectures (pinned at commit 96343eeb5990ff13735e728cd0195eff0156a3bb on Lean v4.33.1 and Mathlib 0df444a360ea). No human reads the resulting tactic scripts line by line. Instead, the candidate proof is treated as untrusted input that may attempt—intentionally or via reward-hacking—to:

  • Alter the target problem by redefining upstream predicates, overriding local typeclass instances, or adding vacuous hypotheses;
  • Import or transitively reference an upstream declaration whose own body still rests on sorryAx;
  • Substitute compiled native code for logical reduction via native_decide, @[extern], or @[implemented_by];
  • Manipulate the Lean environment during elaboration via metaprogramming (run_cmd + addDecl with debug.skipKernelTC enabled); or
  • Tamper with lakefile.toml, lean-toolchain, cached .olean artifacts, or dependency checkouts in .lake/packages/.

2. The 5-Layer Verification Pipeline

The driver scripts/check.py accepts a claim only if five sequential layers pass, recording the SHA-256 hash of the trusted verifier base alongside every ledger entry:

Layer 1 — Workspace & Dependency Integrity (integrity)

Before inspecting any Lean source, check.integrity() verifies that lean-toolchain, upstream.json, lakefile.toml, and lake-manifest.json agree on the exact toolchain (leanprover/lean4:v4.33.1), formal_conjectures commit, and mathlib revision. For every dependency in .lake/packages/, it verifies git rev-parse HEAD and enforces an empty git status --porcelain --untracked-files=all working tree so neither tracked upstream theorems nor untracked helper files can be planted inside dependencies.

It also rejects executable Lean lakefiles (lakefile.lean) altogether and audits lakefile.toml against 15 forbidden build keys (moreLeanArgs, weakLeanArgs, moreServerArgs, plugins, dynlibs, loadDynlibPaths, precompileModules, nativeFacets, etc.) and trust-weakening patterns (debug., skipKernelTC, trustLevel, trust).

Layer 2 — Dual-Pass Source Lint (lint)

scripts/lint.py walks the transitive OpenProofs.* source import closure of a candidate module and enforces role-specific policies (result vs. statement):

  • Comment/string-stripped code rules: A custom lexer strips line comments, nested block comments (/- ... -/), string literals, and character literals while preserving line numbers, then scans against word-boundary bans covering placeholders (sorry, admit, stop), axioms and non-terminating/foreign declarations (axiom, opaque, unsafe, partial, implemented_by, extern, export, csimp, @[init]), native evaluation (native_decide, +native, ofReduceBool, reduceBool, trustCompiler), syntax/elaborator extensions (macro, syntax, elab, notation), metaprogramming execution (run_cmd, run_elab, run_meta, run_tac, #eval), and environment APIs (addDecl*, modifyEnv, setEnv, Lean.Elab, Lean.Kernel).
  • Unstripped raw-text scan: For high-impact tokens (sorry, admit, native_decide, implemented_by, skipKernelTC, ofReduceBool, trustCompiler, run_cmd, #eval, addDecl*), the linter also scans the raw unstripped file. Even if a malformed string or comment delimiter attempted to confuse a source lexer, those tokens cannot appear anywhere in candidate files.
  • Import allowlisting & statement purity: Candidate proofs may import only Mathlib, Batteries, Aesop, Plausible, FormalConjectures*, and OpenProofs.{Results,Lib}.*. Self-recorded negation/variant statements under OpenProofs/Statements/ are restricted to pure theorem ... := sorry declarations—banning def, abbrev, instance, structure, notation, and variable so statement files cannot smuggle altered definitions.

Layer 3 — Artifact Purge & Clean Build (build)

Before invoking lake build, clean_outputs() deletes all existing .olean, .ilean, and IR artifacts under .lake/build/lib/lean and .lake/build/ir for every candidate module in the source import closure. This prevents stale-artifact mismatches where edited source passes the linter while downstream environment inspection reads an older pre-compiled .olean.

Layer 4 — Compiled Environment Audit (opcheck)

Source linting is defense in depth; the authoritative semantic check is OpenProofsChecker/Main.lean (opcheck), a standalone Lean 4 binary that inspects compiled .olean files at runtime. Crucially, opcheck loads both the candidate module and the pinned reference module with extension hooks disabled: 

let env <- importModules #[{ module := args.module }, { module := args.refModule }] {}
  (trustLevel := 0) (loadExts := false) (level := .private)

Setting trustLevel := 0 and loadExts := false ensures no @[init] procedures, environment-extension hooks, or custom pretty-printers from candidate code execute inside the checker process. opcheck then evaluates nine structured checks:

  1. module_origins: Resolves canonical filesystem paths (IO.FS.realPath) for every loaded module's .olean, classifying each strictly into core, package:<name>, or candidate, and failing on any unknown origin.
  2. ref_trusted: Confirms the reference declaration is a .thmInfo declared directly inside the named reference module—either inside .lake/packages/formal_conjectures (for upstream claims) or OpenProofs.Statements.* (for variant claims).
  3. theorem_found: Verifies the candidate declaration is a non-unsafe .thmInfo originating in candidate code, blocking attempts to point a claim directly at an already-proved upstream theorem or at an axiom.
  4. statement_match: Aligns universe parameters and tests whether the candidate theorem's elaborated Expr type is syntactically identical to the reference theorem's Expr type (syntactic identity). When elaboration chooses different but definitionally equal typeclass instance paths, opcheck constructs a synthetic bridge declaration (theorem _opcheck_statement_bridge : <refType> := <candidateThm>) and submits it directly to Kernel.Environment.addDecl (kernel-defeq identity).
  5. statement_consts: Checks refCi.type.getUsedConstants to ensure every constant mentioned in the target statement resides in trusted core, Mathlib, or upstream modules—never candidate code.
  6. axioms: Performs an explicit recursive body traversal (walkAxioms) across .defnInfo, .thmInfo, .opaqueInfo, .axiomInfo, and .inductInfo constants without trusting cached axiom lists in .olean metadata. Only propext, Classical.choice, and Quot.sound are permitted; missing constants become loud sentinel failures.
  7. closure_clean: Confirms candidate modules never import OpenProofs.Statements.* or OpenProofsChecker.*.
  8. candidate_decls: Iterates over every constant (including private declarations via privateToUserName?) across all candidate modules in the import closure. Rejects axiom, opaque, quot, unsafe, partial, @[implemented_by], @[extern], @[export], and @[init]; requires every declaration to live under the OpenProofs. namespace (with a narrow, verified exception for Lean's on-demand equation theorems f.eq_<digits>, f.eq_def, and f.eq_unfold generated for trusted definitions); and checks properSuffixes so no candidate definition, structure, or instance can shadow a trusted name.
  9. kernel_replay: Re-reads raw module data parts and replays every candidate module's constants from scratch atop its clean imports via env.replay.

Layer 5 — Independent Toolchain Kernel Replay (leanchecker)

Finally, scripts/check.py invokes the Lean toolchain's standalone lake env leanchecker <module> on every candidate module in the import closure, providing an independent process-isolated kernel verification pass.

3. Adversarial Bypass Taxonomy (48 Self-Test Expectations)

A verifier without negative tests inevitably drifts as compiler internals evolve. tests/run_adversarial.py runs 48 automated expectations across three test groups: 10 source-linter parser-evasion tests, 9 workspace/lakefile integrity tamper probes, and 29 end-to-end Lean modules specified in tests/adversarial/cases.json (25 bypass/hygiene rejection cases plus 4 positive controls such as kernel decide and compiler-realized equation lemmas).

Crucially, cases.json asserts both must_fail and must_pass checks per module. Verifying that specific downstream layers reject a bypass even when orthogonal checks pass proves that defense in depth actually holds—for example, confirming that opcheck catches semantic shadowing or skipKernelTC tampering independently of the Python source linter.

Bypass Category Representative Test Cases Mechanism & Catching Layers
Compiler & FFI substitution Extern, ImplementedBy, NativeDecide, OpaqueDecl, UnsafePartial, lint/csimp_flagged @[extern] and @[implemented_by] bind logical definitions to arbitrary C or replacement Lean functions during compiled evaluation, while native_decide introduces Lean.ofReduceBool / Lean.trustCompiler axioms to trust native code execution. Caught by lint, opcheck:axioms (for native_decide), and opcheck:candidate_decls (inspecting compiler attribute tables on .olean constants).
Axiom smuggling & placeholder laundering SorryDirect, MacroSorry, SorryViaUpstream, ImportsStatement, LibSorryUse, CustomAxiom, AxiomClaim Hiding sorry inside a tactic macro, declaring the target theorem itself as an axiom, or proving an open problem by citing the upstream theorem's own sorry-backed declaration (SorryViaUpstream passes lint and statement_match!). Caught by opcheck:axioms full body walk (detecting sorryAx or custom axioms), opcheck:theorem_found, and opcheck:closure_clean.
Definition & instance shadowing ShadowDef, InstanceOverride, WeakenedStatement, CandidateDef, FakeEqLemma Redefining Erdos349.IsGoodPair locally as True so the surface syntax matches upstream while the elaborated Expr differs (ShadowDef), or registering a high-priority local instance : LE ℕ where ≤ resolves to True (InstanceOverride). Both pass lint and axioms, and are caught deterministically by opcheck:statement_match and opcheck:candidate_decls suffix-shadowing checks.
Environment tampering (kernel bypass) SkipKernelTC Uses set_option debug.skipKernelTC true inside run_cmd to call addDecl with a theorem of type False backed by True.intro. Notice that statement_match and axioms both pass because no axiom constant appears in the term! Caught across three layers: lint, opcheck:kernel_replay, and leanchecker.
Lexer evasion & build tampering char_literal_quote_cannot_hide_sorry, nested_comment_close_handled, tracked_upstream_edit_rejected, lakefile_rejects:* Probes single-quote character literals ('"'), unterminated strings, nested comments (/- /- -/ ... -/), edits/untracked files inside .lake/packages/formal_conjectures, lakefile.lean injection, and moreLeanArgs = ["-Ddebug.skipKernelTC=true"] in lakefile.toml. Caught by lint (stripped + raw dual scan) and integrity.

4. Finding Upstream Misformalizations via Negation Proofs (#7590)

Running automated proof search behind a strict checker has a useful side effect: when an open mathematical conjecture appears "disproved" in seconds, the verifier confirms whether the formal Lean statement genuinely contradicts itself. Across 142 verified claims in open-proofs (131 proved targets and 11 misformalization certificates), automated triage identified a recurring specification defect in open value-question theorems in google-deepmind/formal-conjectures.

In Lean formalizations of "determine the value of X" problems, upstream uses an answer(...) placeholder constant intended to be filled in once solved. When a theorem quantifies over an input parameter (such as an upper bound N, dimension n, progression length k, or real constant c), typing the placeholder as a fixed constant rather than a function of that parameter asserts that a single parameter-independent value satisfies the predicate simultaneously for all parameters.

On October 24, 2026, I reported eight affected declarations across seven upstream files in google-deepmind/formal-conjectures#7590 (following earlier upstream reports on the same pattern), accompanied by answer-free machine-checked negation proofs verifying that each formal statement is false for every possible choice of placeholder:

Upstream Declaration Omitted Parameter Machine-Checked Counterexample Mechanism
erdos_142, erdos_142.variants.isTheta k : ℕ r 0 N = N whereas r 2 N ≤ 1; no single function is asymptotic or Θ to both.
erdos_319 N : ℕ Maximum admissible set size is ≤ 1 at N = 1, but ≥ 3 at N = 6 via {2, 3, 6} since 1/2 - 1/3 - 1/6 = 0 with no vanishing nonempty proper subset.
erdos_321 N : ℕ R 0 = 0 while R 1 ≥ 1.
erdos_361 c : ℝ At n = 2, the quantity equals 0 for c = 1/4 and 1 for c = 1.
erdos_409.variants.sigma n : ℕ Least iteration count is 0 at n = 2 and positive at n = 6 (σ(6) - 1 = 11 is prime).
erdos_503 n : ℕ In ℝ^0 the maximum size is at most 1; in ℝ^1 it is at least 2.
erdos_692.parts.ii n : ℕ Setting n equal to candidate answer m yields δ₁(m, m) = 0, whereas δ₁(m, m + 2) = 1/(m + 1) > 0.

Rather than depending on the upstream sorry-backed answer constant (which Layer 4's axioms walk would rightly reject due to sorryAx), each certificate proves the universally quantified negation directly. For example, in P319_no_constant_answer.lean: 

theorem erdos_319.no_constant_answer : ∀ a : ℕ, ¬ ∀ N : ℕ, IsGreatest
    { #A | (A) (_ : A ⊆ Finset.Icc 1 N)
      (_ : ∃ δ : ℕ → ℤˣ, ∑ n ∈ A, (δ n : ℚ) / n = 0 ∧
        ∀ A' ⊂ A, A'.Nonempty → ∑ n ∈ A', (δ n : ℚ) / n ≠ 0) } a

Every negation proof compiles cleanly against formal-conjectures 96343ee, passes all five checker layers, and depends exclusively on the standard axioms {propext, Classical.choice, Quot.sound}. The fix is straightforward and structural: parameterize the answer definition over the quantified variable (e.g., def erdos_319.answer : ℕ → ℕ := sorry applied as erdos_319.answer N).

Human-Gated Disclosure Policy Autonomous agents in open-proofs are strictly prohibited from opening issues, submitting pull requests, or posting externally. Candidate findings are written exclusively to local draft files in outbox/ for manual human verification and explicit AI disclosure prior to any upstream report.

5. Reproducibility & Audit Artifacts

lake exe cache get
lake build

python3 tests/run_adversarial.py     # run all 48 adversarial bypass expectations
