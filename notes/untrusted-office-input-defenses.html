Screening Untrusted Office Inputs Before LLM Triage

Accounts-payable, billing, and vendor-support queues ingest emails, attachments, and CSV schedules from unauthenticated external senders. inbox-guard is a zero-dependency Node.js library that screens inbound office artifacts and tokenizes structured PII before text reaches an external language model or an operator's spreadsheet client. This note documents the implementation in src/ and its exact scope boundaries.

1. Attachment Canonicalization & Magic-Byte Screening (src/attachment.mjs)

Checking only MIME headers or path.extname() misses visual extension spoofing, OS-specific filename canonicalization quirks, and renamed native binaries. checkAttachment({ filename, headBytes }) (lines 132–423) evaluates filename normalization and leading byte signatures independently, returning every matching finding:

Filename Canonicalization, Bidi Overrides & OS Edge Cases

  • Unicode bidirectional spoofing (UNICODE_BIDI_SPOOF, lines 28, 145–151): Matches /[\u061C\u200E\u200F\u202A-\u202E\u2066-\u2069]/. Right-to-Left Override (U+202E) flips the displayed character order of an extension so invoice_\u202Efdp.scr renders visually as invoice_rcs.pdf while ending in .scr on disk.
  • Windows/SMB trailing dots, NTFS streams & null-byte truncation (lines 161–230): Windows and SMB strip trailing dots and spaces when writing files to disk, turning invoice.exe. or invoice.exe back into an executable .exe. checkAttachment flags trailing dots/whitespace (TRAILING_DOT_OR_SPACE), NTFS : Alternate Data Stream syntax (NTFS_ADS_FILENAME), directory traversal or drive prefixes (PATH_TRAVERSAL_FILENAME), deceptive Unicode/null extension padding (EXTENSION_PADDING), and ASCII control bytes (CONTROL_CHAR_FILENAME), while canonicalizing the underlying basename and pre-null segment (invoice.exe\x00.pdf) so the hidden terminal extension is still classified.
  • Extension policy sets (lines 1–26, 231–285): Classifies extensions into 75 blocked executable/script/macro/query formats (BLOCKED_EXTENSIONS: .exe, .scr, .lnk, .msi, .ps1, .hta, .iso, .dmg, .docm, .xlsm, .xll, .iqy, .slk, etc. → BLOCKED_EXTENSION), 12 active local markup formats that execute JavaScript or external loads when opened locally (ACTIVE_CONTENT_EXTENSIONS: .svg, .svgz, .html, .htm, .xhtml, .mhtml, .xml, .xslt, etc. → ACTIVE_CONTENT_EXTENSION), and 16 archive container formats whose inner entries have not been unpacked and screened (ARCHIVE_CONTAINER_EXTENSIONS: .zip, .7z, .rar, .tar, .gz, etc. → UNINSPECTED_ARCHIVE_CONTAINER). Multi-dot filenames pairing one of 14 benign document tokens with a blocked or active terminal extension (e.g., PO_1042.pdf.exe or receipt.pdf.svg) emit DOUBLE_EXTENSION_DECOY.

Leading Magic-Byte Verification & Truncated-Buffer Handling

When headBytes (Uint8Array, ArrayBuffer, TypedArray, or byte array) is provided, classifySignatureMatch (lines 70–82) distinguishes three outcomes—"match", "truncated", and "mismatch"—so empty or short slices emit TRUNCATED_OR_EMPTY_BYTES instead of returning a false-clean pass or a false format-mismatch claim:

Finding Code Signature / Condition (src/attachment.mjs) What It Catches
EXECUTABLE_MAGIC_BYTES 4D 5A (MZ PE), 7F 45 4C 46 (\x7FELF), Mach-O / Java class headers (CF FA ED FE, FE ED FA CF, CE FA ED FE, CA FE BA BE), or #!/ shebang Native Windows, Linux, or macOS binaries and scripts renamed to benign document extensions like wire-instructions.pdf.
ARCHIVE_MAGIC_MISMATCH Rar!\x1A\x07, 7z (37 7A BC AF 27 1C), or gzip (1F 8B) bytes on a non-archive extension Compressed archives masquerading as flat documents.
PDF_HEADER_MISMATCH, PNG_HEADER_MISMATCH, JPEG_HEADER_MISMATCH, GIF_HEADER_MISMATCH, OOXML_HEADER_MISMATCH Claimed .pdf, .png, .jpg/.jpeg, .gif, or .docx/.xlsx/.pptx lacking its required header (%PDF-, 8-byte PNG, JPEG SOI, GIF87a/89a, or PK/OLE2) Header spoofing before files reach downstream PDF, image, or Office parsers.
HTML_SCRIPT_IN_PLAINTEXT Leading 4 KB of .csv or .txt (including null-interleaved UTF-16) containing <script, <!doctype html, <html, <svg, <iframe, or <hta: HTML smuggling and active script payloads disguised as plaintext exports.

2. CSV Formula Neutralization & RFC-4180 Serialization (src/csv.mjs)

Spreadsheet applications interpret cells starting with =, +, -, or @—including cells preceded by leading control whitespace or wrapped inside leading quotes ("=CMD...")—as formulas or DDE expressions when a CSV is opened.

Quoting every cell starting with - follows generic OWASP CSV guidance, but breaks back-office accounting exports where negative currency figures (-$1,250.00, -€99.95), decimals (-1,420.55, -.50), percentages (-12.5%), and parenthesized credit balances (($1,250.00)) are routine numeric values. In src/csv.mjs (lines 37–57): 

const FORMULA_TRIGGERS = new Set(["=", "+", "-", "@"]);
const LEADING_CONTROL_OR_QUOTE_RE = /^[\x00-\x20\u00A0\uFEFF"]+/;
const LEADING_CONTROL_CHAR_RE = /^[\x00-\x1F\x7F]/;
const SAFE_NEGATIVE_NUMBER_RE = /^-\s?[$€£¥]?(?:\d+(?:,\d{3})*(?:\.\d+)?|\.\d+)%?$/;

export function isFormulaInjectionCell(value, { allowNegativeNumbers = true } = {}) {
  if (typeof value !== "string" || value.length === 0) return false;

  const stripped = value.replace(LEADING_CONTROL_OR_QUOTE_RE, "");
  if (stripped.length === 0) return false;

  const first = stripped[0];
  if (!FORMULA_TRIGGERS.has(first)) return false;

  // Never exempt `-` when preceded by ASCII control characters (\t, \r, \n, \x0B, \x0C, etc.)
  if (LEADING_CONTROL_CHAR_RE.test(value)) return true;

  if (first === "-" && allowNegativeNumbers) {
    const candidate = trimTrailingSpaceAndQuotes(stripped);
    if (candidate.length <= 64 && SAFE_NEGATIVE_NUMBER_RE.test(candidate)) {
      return false;
    }
  }

  return true;
}
  • Control-character & quote-wrapped triggers: LEADING_CONTROL_OR_QUOTE_RE strips leading ASCII control characters (\x00-\x1F, including \t, \r, \n, vertical tab \x0B, and form feed \x0C), spaces, NBSP, BOM, and leading double quotes before testing FORMULA_TRIGGERS, and LEADING_CONTROL_CHAR_RE blocks the negative-number exemption whenever an ASCII control character leads the cell (such as \x0B-1250.00).
  • Strict negative-balance grammar: Only bounded numeric strings matching SAFE_NEGATIVE_NUMBER_RE pass untouched; cell references and arithmetic expressions after a minus sign (-$A1, -SUM(A1:A4), -1+1) fail the match and receive a leading '.
  • Parsed array contract & serializeCsvRow (lines 79–132): sanitizeCsvRows(rows) operates on parsed 2D cell arrays (string[][]) and logs { row, column, originalPreview } coordinates. serializeCsvRow(row) sanitizes cells idempotently and formats an RFC-4180 row, doubling internal " characters and quoting fields containing commas, quotes, CR/LF, tabs, vertical tabs, form feeds, or outer whitespace.

3. Header Spoofing, Plane-14 Tags & CSS-Hidden Markup (src/email.mjs)

Inbound HTML mail routed into automated triage can conceal text from human reviewers while exposing it verbatim to HTML-to-text extractors. inspectInboundEmail (lines 386–470) runs four deterministic checks using linear O(n) scanners to avoid regex backtracking on malformed HTML:

  1. RFC 5322 / RFC 2047 sender spoofing (FROM_DISPLAY_NAME_SPOOF & REPLY_TO_DOMAIN_MISMATCH, lines 290–427): parseMailboxHeader decodes RFC 2047 Base64/Quoted-Printable words and locates the angle-bracketed mailbox outside quoted display strings. If a display name embeds a different email address than the actual sender—such as "ceo@company.com" <attacker@evil.com>—it flags FROM_DISPLAY_NAME_SPOOF without false-flagging benign headers where display name and mailbox match ("ap@x.com" <ap@x.com>). Cross-domain Reply-To headers emit REPLY_TO_DOMAIN_MISMATCH.
  2. Invisible Unicode & Plane-14 Tag stripping (INVISIBLE_UNICODE_CHARS, lines 3–4, 429–438, 466–467): Matches soft hyphens (U+00AD), grapheme/bidi controls, zero-width spaces/joiners, Plane-14 Unicode Tags (U+E0000..U+E007F), and Variation Selectors Supplement (U+E0100..U+E01EF)—including entity-encoded forms in HTML—escalating severity to high at 8+ characters and stripping them from sanitizedSubject and sanitizedText.
  3. Entity- & escape-normalized HTML/CSS hiding (HIDDEN_HTML_CONTENT, lines 6–110, 142–237): Before testing HIDDEN_HTML_STYLE_RE, containsHiddenCssDeclaration decodes HTML decimal, hex, and named character references (&#58;, &#x3a;, &colon;), strips CSS /*...*/ comments (catching display:/**/none), and resolves CSS hex/character backslash escapes across both inline style attributes and <style> blocks. Checks cover display:none, visibility:hidden|collapse, opacity:0 / .0 (with negative lookahead (?![.\d]) so opacity:0.8 passes), font-size:0, color:transparent, zero-alpha rgba()/hex colors, off-screen negative offsets (left:-9999px), transform:scale(0), and clip-path:inset(50%|100%), alongside DOM attributes hidden, aria-hidden="true", <input type="hidden">, and <template>.
  4. Normalized override phrase scan (INSTRUCTION_OVERRIDE_PATTERN, lines 9–16, 239–288, 448–462): Strips HTML comments/tags, decodes entities, and strips INVISIBLE_UNICODE_RE before matching explicit instruction-override phrases so interleaved zero-width characters or inline formatting tags cannot split keywords.

4. Single-Pass Session-Scoped PII Tokenization (src/redact.mjs)

createRedactor() (lines 56–115) replaces structured identifiers with deterministic per-session placeholders before text leaves the local process: 

const REDACT_RE = new RegExp(
  `(?<email>${EMAIL_SRC})|(?<ssn>${SSN_SRC})|(?<intlPhone>${INTL_PHONE_SRC})|(?<account>${ACCOUNT_SRC})|(?<nanpPhone>${NANP_PHONE_SRC})|(?<literal>${LITERAL_TOKEN_SRC})`,
  "g"
);
const RESTORE_TOKEN_RE = /<(?:EMAIL|SSN|PHONE|ACCOUNT|LITERAL)_\d+>/g;
  • Single-pass tokenization & literal placeholder isolation: redact() matches standard and quoted RFC 5321 emails, hyphenated US SSNs (excluding unassigned SSA prefixes 000, 666, 900–999), +-prefixed ITU-T E.164/E.123 international phones (7–15 digits, optional (0) trunk markers and ext/extension/x suffixes), 12–19 digit contiguous or grouped account/card numbers, and NANP phones in one combined pass. Any pre-existing <EMAIL_n> / <PHONE_n> text already present in untrusted input is captured by the literal branch and mapped to <LITERAL_n> so untrusted senders cannot forge or probe session tokens.
  • Single-pass restoration immune to second-pass expansion: Rather than looping replaceAll sequentially over token entries, restore() runs a single callback pass over RESTORE_TOKEN_RE. If an original redacted string itself contained literal <PHONE_1> text, restoring an outer token never triggers a second substitution pass or $& replacement-string expansion.

5. Scope & Known Limitations

inbox-guard is a pre-triage screening layer; its exact threat boundaries are documented here and in inbox-guard/README.md:

  • Regex PII scope vs. unstructured entities (src/redact.mjs): Tokenization is pattern-based. It does not detect free-text person or company names, street addresses, alphanumeric IBANs, unhyphenated 9-digit SSNs (omitted to avoid false positives on 9-digit routing and PO numbers), or domestic non-NANP phone numbers written without a leading + country code. Mappings exist only in local process memory for one session.
  • Leading magic bytes vs. deep container / polyglot inspection (src/attachment.mjs): checkAttachment checks filenames and leading header bytes at offset 0. It does not unpack archives, run antivirus signatures, detect polyglot payloads appended after a valid %PDF- header, or parse internal PDF object streams (e.g., /JavaScript or /OpenAction dictionaries) or OOXML zip members for external template injection. Archive formats are flagged UNINSPECTED_ARCHIVE_CONTAINER so callers unpack and inspect inner files inside an isolated sandbox.
  • Static HTML/header screening vs. mail-gateway auth & semantic prompt injection (src/email.mjs): inspectInboundEmail inspects RFC 5322 header strings and static HTML/CSS hiding rules; cryptographic sender authentication (SPF, DKIM, DMARC) must still be enforced by the receiving mail gateway, and full CSS cascade / foreground-matching-background contrast across nested tables is not rendered. Similarly, INSTRUCTION_OVERRIDE_PATTERN rules are static phrase heuristics that an attacker can paraphrase in plain visible prose—never a substitute for privilege separation, tool allowlists, and mandatory human approval before outbound sends or financial actions (see Kestrel's security design).
  • Parsed 2D arrays vs. raw CSV streams (src/csv.mjs): sanitizeCsvRows expects already-parsed 2D cell arrays from an RFC-4180 parser, and prefixing dangerous cells with ' leaves a visible leading apostrophe when read by non-spreadsheet tools.
